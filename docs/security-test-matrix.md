# CLPR security test matrix

The catalogue of attack vectors CLPR has considered, what defends against each, and where that
defence is asserted. This is the canonical list: `test/security/` implements it, and each test that asserts a row
names it in a `@custom:matrix-row` NatSpec tag (`@custom:matrix-row X1` asserts row X1).

Rows are numbered consecutively within each section. Removing a row renumbers the rows after it,
and the same change updates every `@custom:matrix-row` tag and every cross-reference in this file.

Classification: `E` executable/new · `E*` executable/already asserted elsewhere · `D`
documented-only · `N` no defence exists · `deferred` the vector exists only under the
`ChannelSyncData` model (#400), so the row stays listed until that lands.

## How this maps to tests

Beyond its `@custom:matrix-row` tag, a test says only what it attacks and why; this document is where
the mapping and the policy live, so read it here rather than expecting a test to explain the scheme.

| File | Holds |
|---|---|
| `test/security/AccessControlAttacks.t.sol` | Attacks on privileged operations: who may call them, what they reach, which values must never move |
| `test/security/BundleAttacks.t.sol` | Multi-step attacks on inbound bundle processing |
| `test/security/MessagingAttacks.t.sol` | Reentrancy through a connector callback; early eviction of a connector with messages in flight |
| `test/security/ChannelAttacks.t.sol` | The close sequence with messages in flight |
| `test/security/VerifierAttacks.t.sol` | A channel's binding to its verifier |
| `test/security/SecurityAssertions.sol`, `SecurityTestBase.sol`, `ReentrantConnector.sol` | Shared assertions, the service-level base, and the reentrant attacker |

A row's test lives wherever its fixtures already are, which is not always `test/security/` — V11
sits in `EthMainnetComplianceTest` because reaching that guard needs a proof the sync committee
signed. The "Suite / notes" column names the owning test either way.

**`E*` rows have no test here on purpose.** A guard that a component suite already asserts at this
level is cross-referenced, not copied: a second copy is two places to update and no extra evidence.
What this suite adds instead is multi-step scenarios — chains of guards, and the state a failed
attack leaves behind, which a component test cannot show because it stops at its own revert.

Citations name a **file and a symbol**, never a line — a symbol survives edits and is greppable.
Slot numbers and byte lengths are quoted together with the constant that proves them.

61 vectors: 13 verifier, 15 bundle, 9 messaging, 12 channel, 12 access control.

## 1. Verifier attacks

The errors in `ClprTypes` are **service-layer** errors; verifiers almost never use them and declare
their own instead. The only `ClprTypes` errors any verifier raises are `VerifyFailed(string)`
(HieroVerifier only) and `ClprBundleStartsAtOrBeforeAcked` (the shared EVM base, Sei and Hiero; see
V13). `MockAvalancheVerifier` performs **no** cryptographic verification — its
`verifyBundle` is `pure` and returns the `QueueMetadata` and payloads decoded from the proof bytes
as-is (`ClprProtobuf.decodeBundleContent`, which ends a message-bearing bundle at `nextMessageId - 1`) — and
is excluded from the compliance gate by the `Mock` prefix rule in `VerifierComplianceCoverage`.

## 2. Bundle attacks

Entry chain: `ClprService.submitBundle` → `BundleLogic.submitBundle` (`nonReentrant onlyService
whenEnabled`) → `BundleLib.processBundle` → `_validateAndPrepare` / `_applyBundle`.

`BundleLib` reads local state from `_channels[channelId]`, and the verifier returns
`(QueueMetadata, messagePayloads, newTrustAnchor, newTrustAnchorId, newEndpointManifest)`. A bundle's
payloads are the contiguous run of the peer's messages ending at `QueueMetadata.lastMessageId`, whose
proven running hash is `lastMessageRunningHash` (V13). The run may be a prefix of the peer's queue
(`lastMessageId < nextMessageId - 1`), while `nextMessageId` and `sentRunningHash` are the peer's latest
state. A payload-free bundle carries `lastMessageId` 0.
